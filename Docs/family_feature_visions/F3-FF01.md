# F3-FF01 Nexus Resident Access And Quick Actions

Family Feature Vision ID: `F3-FF01`
Parent FAM: `FAM-003`
Feature Category: `Nexus Resident Access And Quick Actions`
Category-Level Purpose: `Define the durable resident tray and quick-access product category as a doorway into Nexus, not the whole command center, while preserving privacy transparency and bounded user-controlled action access.`
USER-Facing Surfaces: `Nexus tray icon, resident tray-icon hover tooltip, compact resident status label or styled status surface outside the native tray menu, compact categorized native tray right-click menu, Quick Access submenu, AI submenu, HUD Dashboard entry, Global Settings entry and minimal Nexus Tray & Quick Access settings foundation, AI Status / Command Center entry, future-gated Privacy Lockdown action when FAM-007 admits a real immediate privacy action, Exit Nexus confirmation, Recording Studio link, Log Viewer Studio link, Create Custom Task link, and future USER-selected quick-access slots.`
Experience Flow: `The USER sees one primary Nexus resident icon, reads a compact state summary through the tray hover tooltip or styled resident/status surface, sees Global Settings plus categorized Quick Access and AI entries in a short native tray menu, configures optional quick-access items in a minimal Nexus Tray & Quick Access settings section, uses any admitted reset-window-position/size route to recover eligible Nexus-owned product windows, and uses larger Nexus surfaces for deep control instead of navigating a large tray command wall.`
Included Capabilities: `Single primary NDAI resident icon by default; tray-icon hover tooltip and compact status label/styled surface for resident status outside the native tray menu; always-visible Open Global Settings and Exit Nexus entries unless a later source-truth owner records an exception; categorized native tray menu with Quick Access and AI submenus where grouping reduces top-level clutter; safety/status doorway through AI Status / Command Center while Privacy Lockdown remains future-gated until FAM-007 admits a real immediate lockdown action; state-dependent optional feature doorways such as Open HUD Dashboard when enabled/admitted; minimal Global Settings shell/window needed for Nexus Tray & Quick Access configuration and feature re-enable/configuration routing; configurable Quick Access slots with a small menu budget; optional Recording Studio, Log Viewer Studio, Create Custom Task, and Create Custom Group shortcuts; future-gated reset-window-position/size route for eligible standalone Nexus-owned product windows when admitted by the owning FAM and FAM-002 geometry standard; dynamic icon, tray-icon hover tooltip, or compact status label state for local-only, provider-off, provider-assisted, privacy-lockdown, listening, automation, degraded, blocked, or recording posture when those modes exist and are approved by their owning families.`
Explicit Non-Goals: `This vision does not approve a second AI tray icon by default, forced Windows system-tray pinning, unhide/unpin prevention, OS-owned Sound/Network/Mic cluster integration, runtime AI execution, provider/model work, memory/cache behavior, recording runtime, installer/shortcut mutation, full app-wide Global Settings implementation, ownership of other FAM settings internals, runtime implementation of window geometry reset actions by itself, or a deep nested tray menu that duplicates Dashboard, NCP, Settings, or future AI Command Center surfaces.`
Durable Feature Element Inventory: `F3-FF01-E01 - Primary Nexus resident icon and compact status doorway; F3-FF01-E02 - stable resident menu route contract for core actions, safety/status doorways, and admitted optional feature doorways, where immutable/unremovable means stable route identity/order/behavior when the route is admitted/enabled rather than forced visibility after USER opt-out; F3-FF01-E03 - configurable quick-access slots capped to a small USER-readable budget, including add, remove, reorder, reset defaults, optional links, labels/icons if applicable, route validity, explicit dirty/save/revert/discard behavior, and state-dependent hidden/disabled behavior; F3-FF01-E04 - privacy and provider state summary that routes detailed truth to AI Runtime And Trust owners; F3-FF01-E05 - cross-family launch links for Recording Studio, Log Viewer Studio, and NCP authoring actions when those owning surfaces exist; F3-FF01-E06 - settings-owned customization and feature-profile model for which optional quick-access and resident feature items appear; F3-FF01-E07 - minimal Global Settings foundation/window for Nexus Tray & Quick Access configuration, where dependency ownership and future-gated route contracts remain in source truth / USER packets unless admitted as real USER-facing settings or route controls under FAM-002-governed visual hierarchy; F3-FF01-E08 - user-accessible reset-window-position/size route for eligible standalone Nexus-owned product windows when admitted by the owning FAM and FAM-002 geometry standard.`
Global Settings Foundation Scope: `FAM-003 may own the minimal Global Settings shell/window foundation only where needed for tray/resident Quick Access configuration. The first owned visible section should be Nexus Tray & Quick Access or Quick Access, not Resident Access by itself. Other owner families must not appear as non-actionable connected-surface/status categories in product Global Settings. They may appear only as real USER-facing settings, admitted route controls, or USER-approved proportional dependency-bounded carry-in; otherwise their ownership and dependency contracts stay in source truth, USER packets, and owning surfaces. Quick Access controls must provide compact selector/list grammar, explicit pending-change state, save/revert/discard behavior, and clear reset-default semantics.`
Optional Feature Route Visibility Model: `Resident tray/menu UI shows core Nexus actions plus enabled/admitted feature doorways. Enabled and available means USER wants the feature and it can run, so the resident route is shown enabled. Enabled but temporarily blocked, errored, or not ready means USER wants the feature but it cannot run right now, so the resident route may be shown disabled/unavailable with an owner-bounded reason. Disabled by USER during setup or in Global Settings means hide that optional feature from active tray/menu UI and route re-enable/configuration through Global Settings or setup. Not installed means hide the optional feature from active tray/menu UI and expose install/setup information only through the appropriate settings/setup owner when source truth allows it. Unsupported means hide the optional feature from active tray/menu UI and expose unsupported explanation in settings/setup/status when source truth allows it, without normal enable controls. Unknown means do not overclaim in the tray/menu; route to settings or owner status until deterministic.`
Native Tray Menu Structure Rule: `The taskbar tray icon right-click menu must stay compact and must not use a long disabled status/header row for AI/provider/privacy state. Top-level native menu order starts with Global Settings, then Quick Access immediately below it, then AI, state-dependent admitted optional doorways when enabled/visible, and Exit Nexus Desktop AI. Quick Access owns USER-configured quick slots and small action shortcuts. AI owns the AI Status / Command Center doorway only until FAM-007 admits deeper AI/provider/privacy controls. Developer and Owner tray categories are deferred to FAM-007 Dev/Owner model planning and must not appear as visible FAM-003 menu placeholders before FAM-007 owns the runtime/status semantics. Status detail belongs in the tray-icon hover tooltip, styled fallback/status surfaces, AI Command Center/status surfaces, or other owning full surfaces rather than widening the native tray menu.`
HUD Dashboard Route Rule: `HUD Dashboard is an optional FAM-006-owned feature doorway from the FAM-003 resident UI perspective. If HUD is enabled and available, show Open HUD Dashboard enabled. If HUD is enabled but temporarily blocked, errored, or not ready, show Open HUD Dashboard disabled with an owner-bounded reason. If USER disables HUD or HUD Overlay during setup or Global Settings, hide HUD rows from active tray/menu UI. If HUD is not installed or unsupported, hide HUD rows from active tray/menu UI and route explanation/setup to Global Settings or setup only when source truth allows. Global Settings/setup is the primary re-enable/configuration place. FAM-003 may present owner-bounded route state but must not own FAM-006 HUD internals. Enable HUD Feature belongs to settings/setup or another source-truth-approved re-enable path, HUD Overlay Deferred is state/explanation rather than a substitute for Open HUD Dashboard, and Open HUD Dashboard is the doorway when HUD is enabled/admitted.`
