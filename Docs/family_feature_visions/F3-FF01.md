# F3-FF01 Nexus Resident Access And Quick Actions

Family Feature Vision ID: `F3-FF01`
Parent FAM: `FAM-003`
Feature Category: `Nexus Resident Access And Quick Actions`
Category-Level Purpose: `Define the durable resident tray and quick-access product category as a doorway into Nexus, not the whole command center, while preserving privacy transparency and bounded user-controlled action access.`
USER-Facing Surfaces: `Nexus tray icon, resident status tooltip/menu, compact Nexus Status panel, Quick Access menu, HUD Dashboard entry, Global Settings entry, AI Status / Command Center entry, Privacy Lockdown action, Exit Nexus confirmation, Recording Studio link, Log Viewer Studio link, Create Custom Task link, and future USER-selected quick-access slots.`
Experience Flow: `The USER sees one primary Nexus resident icon, reads a compact state summary, opens high-value surfaces through short menu entries, configures optional quick-access items in settings, and uses larger Nexus surfaces for deep control instead of navigating a large tray command wall.`
Included Capabilities: `Single primary NDAI resident icon by default; compact status label; unremovable Open HUD Dashboard, Open Global Settings, AI Status / Command Center, Privacy Lockdown, and Exit Nexus entries; configurable Quick Access slots with a small menu budget; optional Recording Studio, Log Viewer Studio, Create Custom Task, and Create Custom Group shortcuts; dynamic icon or tooltip state for local-only, provider-off, provider-assisted, privacy-lockdown, listening, automation, degraded, blocked, or recording posture when those modes exist and are approved by their owning families.`
Explicit Non-Goals: `This vision does not approve a second AI tray icon by default, forced Windows system-tray pinning, unhide/unpin prevention, OS-owned Sound/Network/Mic cluster integration, runtime AI execution, provider/model work, memory/cache behavior, recording runtime, installer/shortcut mutation, or a deep nested tray menu that duplicates Dashboard, NCP, Settings, or future AI Command Center surfaces.`
Durable Feature Element Inventory: `F3-FF01-E01 - Primary Nexus resident icon and compact status doorway; F3-FF01-E02 - immutable core menu entries for HUD Dashboard, Global Settings, AI Status / Command Center, Privacy Lockdown, and Exit Nexus; F3-FF01-E03 - configurable quick-access slots capped to a small USER-readable budget; F3-FF01-E04 - privacy and provider state summary that routes detailed truth to AI Runtime And Trust owners; F3-FF01-E05 - cross-family launch links for Recording Studio, Log Viewer Studio, and NCP authoring actions when those owning surfaces exist; F3-FF01-E06 - settings-owned customization model for which optional quick-access items appear.`
Deferred Feature Carryforward: `Deferred item title: AI Status / Command Center surface; origin planning event: resident tray doorway discussion; feature surface: AI status, provider state, permission state, privacy posture, Trust Journal entry point, and capability-pack status; dependency trigger: FAM-007 and AI Runtime And Trust Architecture admit an AI transparency/control surface; grouping recommendation: group with the future AI Command Center feature category rather than expanding the tray menu; proof expectation: visible privacy/provider status and clear route to detailed AI state; durable disposition: preserve as future-gated cross-family carryforward. Deferred item title: Recording Studio and Log Viewer Studio launch links; origin planning event: resident tray doorway discussion; feature surface: FAM-006 recording/log review surfaces; dependency trigger: FAM-006 admits the user-facing Recording Studio or Log Viewer Studio surface; grouping recommendation: expose only as quick-access links after the owning surface exists; proof expectation: tray link opens the owning polished surface without changing recording state by itself; durable disposition: preserve as future-gated FAM-006 carryforward. Deferred item title: taskbar visibility guidance; origin planning event: resident tray doorway discussion; feature surface: installer, first-run education, and settings guidance; dependency trigger: FAM-008 admits setup or installer guidance for notification-area visibility; grouping recommendation: group with install/first-run setup education; proof expectation: explain Windows-owned visibility limits without claiming forced pinning; durable disposition: preserve as future-gated FAM-008 carryforward.`
Design Options: `Option A uses one primary resident icon plus dynamic status and a small configurable Quick Access menu; Option B adds an optional second AI privacy/status icon only after AI runtime complexity proves one icon cannot communicate privacy state safely; Option C relies on an always-visible HUD/status chip for privacy-critical state when Windows hides tray icons. Codex recommends Option A first with Option C as the privacy fallback and Option B as later USER-gated expansion.`
Proof Expectations: `BP1 must prove the tray is a doorway, not a command center; BP2 must cap menu depth, map immutable versus configurable entries, and route each linked feature to its owning family; BP3 must prove implementation readiness, shortcut/launcher boundaries, privacy-state boundaries, menu-budget constraints, and rollback; Hardening and Live Validation must prove the real USER launcher path, visible tray/menu behavior, privacy status truth, screenshot or video evidence, and USER packet review without using repo docs as live status ledgers.`
Branch Readiness Consumption Notes: `BR1/BR2 should treat this as a FAM-003 feature category that consumes FAM-002 presentation standards for resident-access visual/menu/panel treatment, coordinates with FAM-006 for Monitoring/HUD and recording/log surfaces, FAM-007 plus AI Runtime And Trust Architecture for AI privacy/status truth, and FAM-008 for installer/visibility education. FAM-003 may implement the resident-access UI needed for this FFV because it owns the tray doorway behavior; it should not split every menu link into tiny branches when one coherent resident-access package can prove the doorway model safely.`
BP1 Context Notes: `BP1 should explain why the resident icon exists, which items are immutable, which items are USER-configurable, why deep controls stay in Dashboard/NCP/Settings/AI Command Center, how privacy transparency survives Windows tray hiding, and which cross-family items are future-gated.`
