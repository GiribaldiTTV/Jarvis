# F2-FF01 Nexus UI Reference System

Family Feature Vision ID: `F2-FF01`
Parent FAM: `FAM-002`
Feature Category: `Nexus UI Reference System`
Category-Level Purpose: `Define the durable UI reference-system feature category for Nexus-owned windows, controls, status surfaces, dialog classes, tray/menu doorway surfaces, and visual proof contracts without treating candidate branch evidence as promoted golden proof by inference.`
USER-Facing Surfaces: `Top-level Nexus product windows, child/modal/dialog surfaces, compact window-control clusters, buttons, dropdowns, menus, lists, filters, cards, rows, dividers, status/failure/recovery panels, tray/menu doorway surfaces, settings/command-center surfaces, and USER-facing proof packets when those surfaces are proposed for promotion as reusable references.`
Experience Flow: `The USER, ChatGPT, and Codex can compare a proposed or implemented surface against accepted Nexus references, see which evidence is binding versus candidate-only, understand which element groups and states require proof, and avoid accepting visually inconsistent UI because helper or validator output is green.`
Included Capabilities: `Reference-system schema, promotion packet requirements, missing-proof rows for advanced candidates, durable element inventory, reference classes for windows and controls, deferred candidate preservation, cross-FAM consumption notes, and explicit separation between FAM-002 presentation grammar, candidate evidence, promoted UI reference contracts, design tokens, shared primitives, helpers, validators, and runtime implementation.`
Explicit Non-Goals: `This vision does not promote candidate evidence by itself, mutate runtime UI, implement code-level design tokens or shared primitives, mutate helper/validator/fixture code, create active branch state, create PR/release/issue state, track live adoption status, or maintain a proof evidence ledger in repo docs. Promoted UI reference records, when USER-approved, live in Docs/ui_reference_catalog/.`
Durable Feature Element Inventory: `F2-FF01-E01 - Reference carrier and promotion packet schema; F2-FF01-E02 - Nexus-owned top-level window/frame/chrome reference category; F2-FF01-E03 - compact window-control cluster reference category for close, minimize, maximize, restore, drag, resize, and blocked-control states; F2-FF01-E04 - button/control-state reference category for primary, secondary, danger, disabled, hover, focus, pressed, selected, dirty, loading, empty, and error states; F2-FF01-E05 - dropdown/menu/list/filter reference category; F2-FF01-E06 - modal, child-window, dialog, confirmation, platform-native exception, and troubleshooting-surface reference category; F2-FF01-E07 - status, degraded, blocked, fatal, recovery, support, and diagnostic panel reference category; F2-FF01-E08 - tray/menu doorway reference category; F2-FF01-E09 - Vision-To-Proof and element-group proof carrydown requirements; F2-FF01-E10 - deferred reference, design-token, shared-primitive, helper, validator, fixture, and active-FAM-adoption lanes; F2-FF01-E11 - window geometry / resize / size-state composition reference category for min/default/max/fullscreen behavior, responsive reflow, DPI/multi-monitor posture, and per-FAM carrydown.`

Deferred item title: button/control/dropdown/menu/list/filter reference; origin planning event: Template / Golden Reference runtime proof collection and completion pass; feature surface: controls, selectors, dropdowns, menus, lists, filters, rows, scrollbars, and state grammar across Nexus-owned product windows; dependency trigger: USER-approved promotion with known limitations; grouping recommendation: group with Package B reference records; proof expectation: branch-specific proof for every state claimed by the consuming branch; durable disposition: folded into UIREF-003 as promoted-with-known-limitations baseline grammar. Deferred item title: modal/dialog/status/failure/recovery/tray/settings doorway references; origin planning event: Template / Golden Reference runtime proof collection and completion pass; feature surface: child windows, confirmations, dialogs, error/degraded/recovery panels, support/manual-reporting surfaces, resident doorway, and settings entry surfaces; dependency trigger: USER-approved promotion with source-truth/runtime context and known limitations; grouping recommendation: group by user-visible failure/recovery or doorway class when a consuming branch admits implementation; proof expectation: visual proof plus branch-specific failure-path proof; durable disposition: folded into UIREF-004 as promoted-with-known-limitations grammar. Design Options: `Option A created this FAM-002 FFV and an empty promoted-reference catalog schema first, then required later USER proof/disposition before promotion. Option B would have kept candidate evidence only in planning packets and deferred the catalog until a first reference was accepted. Option C would have promoted candidate surfaces immediately without proof. The accepted path is staged Option A plus the 2026-06-17 USER-approved Package A-E completion pass, which promotes records with known limitations instead of pretending missing runtime states were proven.`
Proof Expectations: `A reference may be promoted only after USER-approved visual evidence or USER waiver, source evidence, applicable and non-applicable surface classes, required element groups, required states, known limitations, adoption rule, and final disposition are recorded. Candidate evidence from branch screenshots, videos, helper output, Live Validation, or USER packets remains evidence until a promotion packet explicitly records the promotion result. Branches consuming this FFV must still prove their own UI through BP2/BP3, Hardening, Live Validation, and USER review where required.`
Branch Readiness Consumption Notes: `BR1/BR2 should use this FFV when a selected feature route creates, evaluates, or standardizes Nexus-owned UI references, templates, controls, or visual proof contracts. The branch must separate binding FAM-002 grammar, candidate evidence, promoted catalog records, and active implementation proof. If no promoted catalog record exists for a needed surface, the branch must use FAM-002 grammar and USER visual proof rather than claiming a golden template exists.`
BP1 Context Notes: `BP1 should explain what reference-system work is being reviewed, which candidate surfaces are only evidence, which missing-proof rows block promotion, what USER will visually inspect, and which references remain deferred or future-gated. BP1 must not imply that a candidate surface is already a promoted reference.`
